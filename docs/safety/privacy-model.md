# Privacy model v1
No identity, biometric templates, stable person keys, trajectory, voice, human image or raw radar public output. Fixed zones near/sector_a/sector_b/sector_c only; human cues use coarse zones, never precise coordinates. Through-obstruction sector definitions must be large enough for the deployment's privacy review; software cannot verify physical size. No cross-zone matching or linking. One bounded evaluation at a time; no observation retention, disk cache, telemetry or outbound connection. JSON output necessarily can be stored by its recipient; fixtures are explicitly synthetic and may be retained. Inputs and errors never echo arbitrary strings. Python memory disposal is not secure erasure; use isolated local processes and host disk/core-dump controls for sensitive deployments. User-supplied stream history is not accepted. Source handles are fixed sensor categories, not person IDs. Score output is bucketed and explicitly uncalibrated when synthetic. Presence absence is never permission to proceed. Privacy tests inspect public schemas, output and module state. Human/privacy review remains mandatory for physical deployments.
