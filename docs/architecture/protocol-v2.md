# Protocol 2 and invariant amendment — frozen before v2 code
Protocol 1 remains byte-compatible with its frozen contract. Protocol 2 uses identical top-level fields plus mode=direct/through_obstruction, version=2. Closed schema rules and all resource limits remain. Adds sensors thermal_person/depth_person; these contain one 0..1 minimized human-presence score, not raw pixels/depth/radar. RGB may now carry a rectangle. Person cue sensors require nonhuman=false and zone=near. Rectangles remain bounded 1%-grid integer geometry, direct view only. Thermal/depth non-human rules still use their original patch units and separate sensors. At most one cue per (sensor,zone); no IDs or arrays of individual people, no retained detections. The one zone-level human envelope may cover multiple people; no count or object correspondence is promised.
In mode=through_obstruction, require authorized_obstruction=true and accept ONLY radar in coarse sectors, never any geometry or person sensor. Direct mode rejects radar sector observations: separate batches keep through-obstruction and direct localization apart. Radar never produces human class. Direct thermal/depth person classifications require upstream documented validation; API input is an assertion, never certification. No current hardware is qualified.
Capabilities/timing/thermal/depth rules remain protocol 1. thermal_person/depth_person contribute human_presence and occupancy_zone in direct near zone. Current independent valid contributors survive invalid peers. Sources list ONLY valid supporting sensor enums. Rejected evidence is represented by bounded reasons, not attribution as support. When an attempted supporting sensor withdraws or disagreement remains, confidence is conservatively capped at medium, score remains uncalibrated and degraded=true. No weighting into a calibrated probability is claimed. Contradictory valid classes/states -> UNKNOWN. Human boxes require all remaining eligible contributors to have identical rectangles; otherwise retain coarse presence with rect=null and localization_uncertain reason. A single valid thermal/depth cue can maintain the rectangle after RGB blackout. All support lost -> human_presence UNKNOWN, rect=null, defensive recommendation. No extrapolation, target lock or person association state.
Invariant v2 replacements: I05 permits direct-view short-lived human envelope geometry; I06 remains strictly coarse through-obstruction; I10 provenance remains synthetic/external_unverified; I11 now explicitly prohibits erasing supported objects just because RGB fails. Other frozen invariants unchanged. Public output format unchanged plus mode for v2. Invalid schema errors never echo content. Snapshot visual geometry expires within <=200ms of evaluation and by each sensor/calibration deadline; re-evaluation with trusted time is required to continue. No hardware accuracy or association guarantee from synthetic tests.
