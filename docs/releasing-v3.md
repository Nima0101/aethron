# v0.2 candidate release procedure
All historical gates plus v3 rows apply. Commit the exact source before clean-clone/release checks. Run `python3 scripts/verify.py`, both60-second fuzzers, full temporal evaluation, pinned lint/security/audit, isolated wheel install, optional actual-model E2E and visual reproduction. `python3 scripts/reproduce.py` clones committed source to a fresh temporary directory, executes quickstart/replay/evaluation, builds twice and compares every release byte. `scripts/package_check.py` builds identical wheels and verifies v2 and v3 consumers outside the source tree.

Run `python3 scripts/release.py` only with clean committed source. The source archive includes licensed evaluation pixels and notices; the stdlib zipapp contains runtime and source licenses. Optional OpenCV/NumPy/model are separately installed and inventoried, not covert zipapp dependencies. Generated SBOM/provenance references code version, data freezes and optional model hash. Source manifests and SHA256SUMS cover the artifact set. Local provenance is unsigned, not a hosted attestation.

The CI matrix now executes true CLI E2E and recorded pixel replay plus regression metrics. The development job reproduces README assets, builds and installs; the vision job obtains hash-pinned weights and runs actual inference on recorded pixels and positive/negative stills. No CI badge until an actual hosted result exists. No release tag/public push while mandatory publication gates remain failed or blocked. Hardware and independent safety/privacy evidence are additional production prerequisites, never inferred from tests.
